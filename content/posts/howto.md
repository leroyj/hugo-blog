## My needs

I'm looking for a solution with no maintenance that helps me to focus on writing content and not maintaining the full system. So don't expect a microservice architectured CMS on AWS Lambda though we might use it for some projects later :)  
I also want a system with multilingual support to write in Globish :gb::us: and French :fr:.

This fits completely the architecture pattern called [Jamstack (Javascript, API, Markup stack)](https://jamstack.org/) that sits on top of pre-rendering and decoupling.

## Hugo: a static website generator

{{< figure src="https://upload.wikimedia.org/wikipedia/commons/a/af/Logo_of_Hugo_the_static_website_generator.svg" title="Logo of the Hugo project" alt="Logo of the Hugo project" height=100 >}}

This blog is generated by [Hugo](https://gohugo.io/) which is a nice static website generator like [Jekyll](https://jekyllrb.com/) or [Gatsby](https://www.gatsbyjs.com/).  
It takes simple [Markdown (md)](https://en.wikipedia.org/wiki/Markdown) files as input and generates your website structure with nice, optimized and fast html files. (don't blame hugo on the accessibility, it's something I need to work on)

{{< figure src="/performance.png" title="Look at these amazing performances!" alt="Look at these amazing performances!" height=250 >}}

By static, it means that no machine or VM is required to run it. You just need to host the files on a _"dumb"_ http drive.
This implies low resources to host and low resources on local machine.

## :art: Theme

I'm using the [m10c](https://themes.gohugo.io/themes/hugo-theme-m10c/) theme slightly customized that I found simple and elegant. I've only tweaked the colors, changed the avatar and modified the list template to add the description.

[Sass](https://sass-lang.com/) is needed to modify the scss files.
You can do it easily on a Mac if you already have npm installed.


## :fr::us: Multilingual support

In order to setup the multilingual support, you need to configure the menu, duplicate the content and add some link to help the user to switch from a language to another.

Unfortunatly, when using multilingual support, the customized 404 page is not working really well with **GitHub Pages**.
**GitHub Pages** only supports a unique 404 page named `404.html` at the root of the repo.
The only way then is to copy the 404 of the language you've chosen and move it at the root folder.
Fortunately this can be automated in the **GitHub Actions** as we will see in the following section.

## :building_construction: Deployment chain

{{< figure src="../deploy_workflow.drawio.png" title="deployment chain diagram" alt="deployment chain diagram" height=200 >}}

I've chosen Github Page as my hosting solution. It is as simple as copy and past the content of the code generated by hugo (usually the `public` folder) and paste it in your `<nickname>.github.io` repo.
To automate the process you can use a repo for the source of your blog content and use **Github Actions** to automate the deployment.
You can follow this [tutorial to integrate Hugo in GitHub](https://ruddra.com/hugo-deploy-static-page-using-github-actions/).
To fix the 404 page issues discussed above, I've just added a step in the `.github/workflows/gh-pages.yml` to copy the English 404.html at the root as seen below.

```yaml {linenos=table,hl_lines=["4-8"],linenostart=24}
      - name: Build
        run: hugo --minify

      - name: copy 404 from en language to root
        uses: canastro/copy-file-action@master
        with:
          source: "./public/en/404.html"
          target: "./public/404.html"

      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        if: github.ref == 'refs/heads/main'
        with:
          deploy_key: ${{ secrets.ACTIONS_DEPLOY_KEY }}
          external_repository: leroyj/leroyj.github.io
          publish_dir: ./public
````

## Google Analytics support [^1]

To follow my tiny audience, I've setup Google Analytices as this is the tool I know and that I can set up for free.
This is really straight forward to configure as you just have to add `googleAnalytics = 'G-YOURGAID'` to your `config.toml` file.

## Asciinema: Terminal screencast support

_"A picture is worth a thousand words"_ so a screen cast.

A screen cast is simply a movie of your action on your computer. Terminal screen cast is exactly the same for text only terminal with the benefits of the lightweight of text only codec. The video stream is minimal (104kB for 2:45min with high quality obviously)
I'm using [asciinema](https://asciinema.org/) nice solution I've embedded in Hugo using the following blog posts:

* [Embedding asciinema cast in your Hugo site](https://jenciso.github.io/blog/embedding-asciinema-cast-in-your-hugo-site/)
* [Custom Fonts in Asciinema](https://www.tonylykke.com/posts/2018/06/18/custom-fonts-in-asciinema/)
